# Vue 3 接入（Vue 3 Integration）

[← 返回目录](./README.md) | ← 上一篇：[开始之前](./01-getting-started.md) | 下一篇：[Vue 2.7 接入](./03-vue2.md) →

> 目标：在最小 Vue 3 工程里用 `/vue3` 正式门面接出「设计器 → 预览 → 打印」。
> 可运行完整示例：`demos/apps/vue3`（9331）。Vue 3 是一等支持路径：门面与旧 `@worm-vue3-print/canvas`
> 组件同形，老项目只换依赖与 import，模板、事件、ref 调用、业务逻辑一行不动。

## 1. 前置条件（Prerequisites）

- 已完成 [01](./01-getting-started.md)：确定打印链路、装好包、理解宿主最小清单。
- Node ≥ 18；一个 Vue 3 工程（下方给出从零创建命令）。
- `core` / `canvas` / `plugin-kit` 同号同批发版（当前 1.6.6），显式装同版本并提交锁文件。
- `vue` 是 `/vue3` 子路径的 optional peer，项目里已有无需额外操作。

## 2. 步骤（Steps）

### 2.1 从零创建工程并安装依赖

```bash
# cwd = 你的工作区
npm create vite@latest my-print-app -- --template vue
cd my-print-app
npm install
npm install @worm-print-platform/canvas @worm-print-platform/core

# 老项目迁移：卸旧装新，import 路径换成 /vue3，业务代码不动
# npm uninstall @worm-vue3-print/canvas @worm-vue3-print/core
# npm install @worm-print-platform/canvas @worm-print-platform/core

npm ls @worm-print-platform/core @worm-print-platform/canvas @worm-print-platform/plugin-kit
```

> 安装后可构建一次确认依赖可解析：`npm run build`。若版本不齐平，先统一再继续。

### 2.2 最小接入（可直接复制运行）

`src/App.vue`：

```vue
<template>
  <PrintDesigner
    ref="designerRef"
    :initial-template="template"
    :fields="fields"
    :is-edit="true"
    :upload-image="uploadImage"
    @save="onSave"
    @preview="onPreview"
  />
  <Teleport to="body">
    <div v-if="previewVisible" class="preview-mask" @click.self="previewVisible = false">
      <PrintHtmlPreview
        ref="previewRef"
        :template-json="previewTemplate"
        :print-data="printData"
        base-url="/files"
        @rendered="pageCount = $event"
        @error="previewError = $event"
      />
      <button type="button" @click="previewRef?.print()">打印</button>
    </div>
  </Teleport>
</template>

<script setup>
import { ref } from 'vue'
import {
  PrintDesigner, PrintHtmlPreview, createDefaultTemplate,
} from '@worm-print-platform/canvas/vue3'

const designerRef = ref(null)
const previewRef = ref(null)
const template = ref(createDefaultTemplate())
const previewTemplate = ref(null)
const printData = ref({ order: { no: 'SO-2026-001' } }) // 替换为真实业务数据
const previewVisible = ref(false)
const pageCount = ref(0)
const previewError = ref(null)

const fields = ref([
  { fieldKey: 'order.no', fieldLabel: '单号', fieldType: 'string', sortOrder: 1 },
  { fieldKey: 'goods', fieldLabel: '商品明细', fieldType: 'list', sortOrder: 2 },
])

// 图片上传适配器：把文件传到你的文件服务，返回可访问 URL
async function uploadImage(file) {
  const form = new FormData()
  form.append('file', file)
  const res = await fetch('/api/upload', { method: 'POST', body: form })
  const { url } = await res.json()
  return url
}

function onSave(json) {
  // json 是模板 JSON 字符串，只含画布 elements；元信息由宿主分开持久化
  const elements = JSON.parse(json)
  fetch('/api/templates/1', {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ elements }),
  })
}

function onPreview() {
  // 门面 getTemplateJson() 返回对象（不是字符串），绕过校验前先 validateTemplate()
  const warnings = designerRef.value?.validateTemplate() ?? []
  if (warnings.length) {
    previewError.value = warnings.join('\n')
    return
  }
  previewTemplate.value = designerRef.value?.getTemplateJson()
  previewVisible.value = true
}
</script>
```

> `base-url="/files"` 是模板内图片等相对资源的基地址，由宿主提供静态资源服务；无图片时可保留。
> `uploadImage` / `onSave` 中的 `/api/*` 是你后端的接口（见 01 宿主最小清单），需按项目实际替换。

### 2.3 组件契约（Component Contract）

`PrintDesigner` props（完整口径见技能 `references/integration-api.md`）：

| prop | 类型 | 说明 |
| --- | --- | --- |
| `initial-template` | `TemplateData \| MultiPageTemplateData` | 初始模板对象 |
| `initial-elements` | `RuntimeElement[]` | 仅无 `initial-template` 时覆盖元素层 |
| `fields` | `PrintBusinessField[]` | 业务字段（`fieldKey/fieldLabel/fieldType/sortOrder`） |
| `is-edit` | `boolean` | 是否可编辑 |
| `upload-image` | `(file) => Promise<string>` | 图片上传适配器，未注入时入口置灰 |
| `upload-design-background` | `(file) => Promise<string>` | 设计背景图上传适配器，未注入时入口禁用 |
| `show-help` / `show-preview` / `show-save` | `boolean` | 工具栏按钮显隐，默认显示；隐藏不影响 `save()` 与事件旁路 |
| `fonts` | `PrintFontDeclaration[]` | 模板级字体声明，保存/导出时写入模板 JSON |
| `design-data` | `object \| object[]` | 插件 UI 的设计态业务数据 |
| `theme` | `'auto' \| 'light' \| 'dark'` | 主题预设，`auto`（默认）跟随系统；只影响外壳，不动纸张 |
| `theme-config` | `PrintDesignerThemeConfig` | 主题色值覆盖对象，优先级高于预设/CSS 令牌 |
| `lang` | `string` | 界面语言（BCP47，如 `ja-JP`）；未传时跟随全局 locale |
| `messages` | `CustomLocaleMessages` | 自定义语言包（对象注入），覆盖内置与插件译文，缺键回退中文 |

事件：`save(json: string)`（首参为模板 JSON 字符串）、`preview()`（无载荷）。
ref 方法：`getTemplateJson()`（返回**对象**）、`validateTemplate()`、`getGeometryWarnings()`。

`PrintHtmlPreview` props：`template-json / print-data / base-url / font-base-url / renderers`；
事件 `rendered(pageCount) / error(err)`；ref 方法 `print / rerender / setViewZoom`。

**不存在** `back` 事件与 `setTemplateMeta` 方法——返回导航与模板元信息都是宿主业务层。多语言用法见 [06 §3.3.1](./06-i18n.md#331-浏览器设计器全局共享-vs-单实例隔离)。

### 2.4 出纸（Printing）

- **A 浏览器打印**：预览层「打印」按钮调 `previewRef.print()`（门面已封装同构渲染 + `contentWindow.print()`）。
- **B 服务端 PDF**：部署 `services/render`，后端代理 `/render/pdf` 并注入 `X-Render-Key`，前端不持密钥。
- **C 静默打印**：`import { PrintClient } from '@worm-print-platform/core/client'`，`connect()` 后 `printHtml(rendered)` 直送本机客户端（绑定 `127.0.0.1`，须与浏览器同机）。

### 2.5 接线市场插件（可选）

安装见 [07](./07-plugin-install.md)。在 `src/main.js` 入口 import 插件副作用模块，并对内核包 dedupe：

```js
// src/main.js
import '../.worm-print/plugins/echarts/dist/marketplace.js'
import { createApp } from 'vue'
import App from './App.vue'
createApp(App).mount('#app')
```

> `/vue3` 门面组件自身处理样式，宿主无需手动引 `canvas/style.css`（只有直接用裸 `<print-designer>` 的 light DOM 形态才需要引）。市场插件的 UI 样式由插件自行注入，也不依赖 `canvas/style.css`。

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
export default defineConfig({
  plugins: [vue()],
  resolve: { dedupe: ['@worm-print-platform/core', '@worm-print-platform/plugin-kit'] },
})
```

## 3. 验证（Verification）

```bash
npm run build                     # 通过
npm run dev                       # 打开页面：设计器渲染、无控制台报错
```

手动核对（决定你是否真的完成）：

- 设计器保存模板 JSON → 刷新/重新打开能回填 elements。
- 点预览 → 渲染出含真实业务数据的页面 → 打印（A）；B/C 按 01 的验收点追加。
- 若装了插件：设计器素材区出现图表元素，切到属性页不报错。

无 GUI / 无桌面浏览器时的等效 smoke：起 `npm run dev` 后用 `curl` 检查 `/`、`/src/main.js`、`/src/App.vue`（及插件入口 `/.../dist/marketplace.js`）返回 200，且 dev server 无编译错误；页面视觉确认留到有浏览器时再做。

## 4. 排错（Troubleshooting）

| 症状 | 原因 / 处理 |
| --- | --- |
| 构建报 `Missing "./i18n" specifier in "@worm-print-platform/core"` | 市场插件依赖 `core/i18n`；旧版 npm `core@1.6.0` 曾缺该导出，1.6.1 已同步修复。**不要把 core 单独换成仓库本地产物**（会因 npm canvas 与本地 core 导出不一致报 `CELL_BORDER_APPLY_HINT* MISSING_EXPORT`）；按 [07 §4](./07-plugin-install.md#4-排错troubleshooting) 的做法把 core / canvas / plugin-kit **三包一起**指向仓库同源构建产物。 |
| 构建报 `Rollup failed to resolve import "echarts/charts"` | 市场 echarts 插件需要 `echarts` 运行时：`npm install echarts@^6.1.0`（见 [07](./07-plugin-install.md)） |
| `:fields="obj"` 在门面上失效 | 门面内部已把 props 转赋 property；确认用的是 `/vue3` 门面而非裸 `<print-designer>` |
| 保存后再打开未回填 | 模板 JSON 与元信息分开存储；用 `initial-template` 传回保存的 elements |

## 5. AI 工具集成提示词（场景差异）

门控、安装、验收的通用模板见 [01 §5](./01-getting-started.md#5-ai-提示词模板唯一模板源)，本场景额外约束：

```text
【宿主框架】Vue 3（SFC + <script setup>），构建器按项目现状。
- 组件从 @worm-print-platform/canvas/vue3 门面导入：PrintDesigner / PrintHtmlPreview，
  无需 isCustomElement、无需手动引 CSS（门面处理样式）、无需手动赋 property。
- 若项目原本用 @worm-vue3-print/canvas：只换依赖与 import，模板/事件/ref/业务逻辑不动。
- 设计器 props 按 02 的契约表；lang/messages 用于多语言（见 06）。
- 事件 save 首参为 JSON 字符串、preview 无载荷；ref getTemplateJson() 返回对象。
- 市场插件在 src/main.js import 副作用模块，并对 core/plugin-kit 做 dedupe（见 02 §2.5）。
【验收】npm run build 通过；保存→回填→预览→打印链路跑通；不虚构 API（无 setTemplateMeta、back）。
```
